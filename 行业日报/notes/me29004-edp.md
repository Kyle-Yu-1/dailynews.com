# 工程设计流程（Engineering Design Process，EDP）

## 一、EDP 是什么
一套**可重复、可记录**的解题流程，把模糊需求变成可制造的实物。它不是线性的，而是不断回环：

需求识别 → 调研 → 提出概念 → 评估与选择 → 详细设计 → 原型制作 → 测试 → 改进 → 沟通/交付

（测试失败要回到「提出概念」或「详细设计」，循环本身就是设计的一部分。）

## 二、各阶段的可操作工具

1. **需求识别**：写清问题陈述（谁、什么场景、痛点）；区分「需求 must / 期望 want」；可测量的指标（重量、成本、强度、时间）。
2. **调研**：现有产品、专利、材料、标准；记录来源。
3. **概念生成**：头脑风暴先求量再求质；至少 3 个不同原理的方案，而不是一个方案的三种变体。
4. **评估选择**：Pugh 矩阵 / 加权评分矩阵，按需求权重打分；记录「为什么选它」。
5. **详细设计**：尺寸、公差、材料、连接方式、成本估算；用草图 + CAD 表达。
6. **原型**：低成本快速验证（纸模 → 3D 打印 → 功能样机），一次只验证一个关键假设。
7. **测试**：按最初定义的可测量指标做实验，写数据。
8. **沟通**：图、表、结论，说明「我如何按流程做决策」。

## 三、WS1 工作表高分思路（结合 100 分作业）

- 开头：**问题陈述 + 约束条件 + 成功标准**，三条都要可验证。
- 中间：3 个概念分别用一句话原理 + 一张草图；用评分矩阵选出最终方案，写明权重依据。
- 结尾：详细设计（关键尺寸/材料/装配）、原型照片与测试结果、个人反思（如果重来会改什么）。
- 老师看的是「决策有据、过程完整」，不是成品是否华丽。

## 四、一眼验真懂（自测）

1. 「需求」和「方案」谁先谁后？为什么不能先画图再想需求？
2. Pugh 矩阵里「权重」代表什么？权重从哪来？
3. 为什么概念生成阶段要求「至少 3 个不同原理」？
4. 原型和最终产品的区别是什么？
5. 测试失败的结论该怎么写进报告？

（答案思路：需求约束方案；权重来自需求优先级；不同原理扩大解空间避免过早收敛；原型只验证关键假设；失败要写明「验证了什么假设、结论、下一步」。）
