# EIE1005 L3 · 虚拟世界中的 AI 与数据分析（Game AI 与强化学习）

## ⏱ 30 秒速览
- **Part I（发展史）**：游戏 AI = 让 NPC 和程序内容“显得有智能”；目标是好玩、有挑战但不过分、公平、守规则、不占资源；FSM 是最早的规则式 AI；机器学习被用于智能 NPC、图形增强、对话生成、故事/世界生成、沉浸感。

## Part I · Development of game AI（Part I p.4–23）

### 1. 什么是游戏 AI（p.5）
- 模仿非玩家角色（NPC）行为的智能 + 程序化内容生成（PCG）。
- 让游戏“感觉真实”；为 NPC 定路径；根据玩家选择为 NPC 做决策；定策略；感知玩家行为；与玩家沟通互动。

### 2. 游戏 AI 的目标（p.6）
- **好玩（Be fun!）**；有挑战但不压倒性（除非最高难度）；避免不公平优势（若用了要公开/平衡）；必须遵守游戏规则；不能独占资源（如 CPU 时间）。

### 3. 游戏 AI 的开端（p.7）
- 1960s–70s 初的 Spacewar!、Pong(1972)、Gotcha 是纯双人对战，无 AI。
- 1970s 出现单机 NPC 模式（Taito《Speed Race》1974）。
- 街机黄金时代《Space Invaders》(1978) 让“AI 对手”流行起来。

### 4. 有限状态机 FSM（p.8–11）
- 早期游戏 AI = 规则系统 **FSM**；最简单基础、动作游戏最常用。
- 四要素：**状态**（定义行为）、**状态转移**、**条件**（转移必须满足）、**事件/动作**（内部或外部产生，可引发转移）。
- 例子：Pac-Man（幽灵的不同状态）；现代 FSM 允许状态内嵌子 FSM。
- 缺点：NPC 行为可预测；只适合简单游戏（状态多则图太复杂）；状态间规则“太清脆”，NPC 显得不自然。
> 🧠拓展：FSM 与行为树、效用 AI 同属“设计师写规则”的传统 AI；机器学习的区别是智能从数据中学来，而不是设计师写死。

### 5. 机器学习在电子游戏中的应用（p.12）
- ML = AI 子领域：算法通过经验和数据自动改进；对数据集做统计分析来训练模型；无需显式编程即可预测/决策（与 FSM 相反，FSM 的智能来自设计师）。
- 五个用途：①更聪明的 NPC ②增强图形 ③对话生成与真实互动 ④故事与世界生成 ⑤营造沉浸感。

### 6. 智能体能否靠“进化”学会玩游戏（p.13）
- 思路：造很多不同“大脑”的 agent → 各自玩一局拿分数 → 选出优秀者生成下一代 → 用一组数字（DNA）控制行为 → 反复迭代越玩越好。
- 循环：Play game → Score agents → Keep the best → Create new agents。
- 例子：进化机器人（ANN 控制）、Flappy Bird / 超级马里奥用神经网络+遗传算法通关。

### 7. 更聪明的 NPC：AlphaGo Zero（p.14–15）
- DeepMind 的 AlphaGo 2016 击败李世石；2017 年 **AlphaGo Zero** 更进一步：不学人类棋谱，**仅靠自我对弈**从零学起，还击败了旧版 AlphaGo。
- 用强化学习 + 深度神经网络（GPU 上运行），比传统 CPU 程序快得多。
> 🔴考点：AlphaGo Zero 与 AlphaGo 的关键区别 = 不依赖人类棋谱、纯自我对弈。

### 8. 增强计算机图形：DLSS（p.16–17）
- 传统引擎高分辨率渲染要降帧率；NVIDIA 的 **DLSS（Deep Learning Super Sampling）** 让引擎先渲染低分辨率（高帧率），再用深度神经网络上采样到目标分辨率。
- 需 NVIDIA RTX GPU + 支持的游戏 + 最新驱动；Minecraft RTX 在 4K 下帧率翻倍而不牺牲画质。

### 9. 对话生成与真实互动：Façade（p.18–19）
- ML + NLP（自然语言处理）+ 情感分析改善 NPC 台词。
- **Façade**：实时互动戏剧，玩家用自然语言输入与 NPC（Trip、Grace）对话，结局随玩家互动改变；NLP 理解输入，行为语言系统决定 NPC 回应。

### 10. 故事与世界生成（p.20–21）
- **AI Dungeon**：文本冒险游戏，用大语言模型按玩家输入实时生成剧情，而不是用巨大决策树写死路径。
- **Minecraft**：用世界种子即时生成海量不同世界，程序只需存生成算法和种子；未来世界生成可交给 ML 按玩家兴趣自适应。

### 11. 营造沉浸感：FIFA 22 HyperMotion（p.22–23）
- 建模真实世界极难；ML 可预测玩家动作的下游效果。
- FIFA 22 的 ML 动画从 870 万帧比赛动作捕捉中学习，实时生成新动画；新战术 AI 让每个 NPC 理解攻防阵型；**HyperMotion 实现 11v11 全球员动画**（旧 AI 每次只驱动 2–3 名球员，其他 NPC 动作失真）。

## Part II · Reinforcement Learning for Game AI（Part II p.4–22）

### 12. 什么是强化学习 RL（p.5–6）
- Agent（AI）通过与环境**试错交互**，以获得的**奖励（正/负）为反馈**学习；游戏 AI 开发常用。
- 与监督/无监督的区别（课件原比喻）：
  - 监督学习：把孩子送进学校，老师总是给答案；
  - 无监督学习：孩子在学校只靠书本和习题，没有老师和答案；
  - 强化学习：把孩子放进工作场所，在工作环境中学习！
- 就像玩家自己反复试玩，不靠任何监督也能越玩越好——这是人类通过互动学习的方式。

### 13. 强化学习框架（p.7）
- **Agent**：NPC、移动物体等；**Environment**：游戏世界。
- **State S_t**：Agent 在 t 时刻的状态；**Action A_t**：Agent 在 t 时刻做的动作；**Reward R_t**：环境在 t 时刻给出的奖励。
- 循环输出序列：S_t, A_t, R_t → R_{t+1}, S_{t+1}；**目标 = 最大化累计奖励**。
> 🔴考点：必背四要素 Agent/Environment/State/Action/Reward；目标是最大化**累计**（长期）奖励，不是单步奖励。

### 14. Q-Learning 与 Q 表（p.8）
- Q-learning = 给定当前状态，为 agent 找“下一步最优动作”的 RL 方法；Q 来自动作在该状态的 **Quality（质量）**。
- Q 表记录每个状态每个动作的 Q 值；每走一步更新一次；**充分探索与训练后，Q 表收敛到最优动作价值**。
- 输入（state, action）→ 输出 Q 值（相对最终目标的价值估计）。

### 15. Q-learning 例子：迷宫老鼠（p.9–10）
- 目标：训练老鼠自动找路吃到最多奶酪、避开毒药；6 个状态、每个状态 4 个动作（上下左右）；Q 表记录每个「状态×动作」的价值。
- **Step 1**：Q 表初始化为全 0。

### 16. Step 2 · 探索 vs 利用（p.11–12）
- **Exploration 探索**：随机试动作以获取环境信息，适合 Q 表还不够“聪明”的初期；
- **Exploitation 利用**：按已知信息最大化奖励，适合 Q 表足够好的后期。
- 由参数 **ε（0≤ε≤1）** 控制：ε = 执行随机动作（探索）的概率；训练初期 ε 大（大多随机探索），训练后期 ε 小（按 Q 表选动作）。
> 🧠拓展：课件用 ε 递减思路；通用做法叫 ε-greedy。Workshop 3 训练代码里用 `np.random.randn(...)*(1./(i+1))` 实现“噪声随训练局数衰减”的探索。

### 17. Step 3 · 执行动作拿奖励（p.13）
- 迷宫奖励方案：无奶酪 +0；小奶酪 +1；大奶酪堆 +10；毒药 −10（死亡）。
- 开局 ε 大→探索模式；老鼠随机向右一步吃到奶酪 → +1 分。

### 18. Step 4 · Bellman 方程更新 Q 表（p.14–17）
- 直觉（p.15）：新 Q 值 = 原 Q 值 + {该动作的奖励 + 因该动作带来的 Q 值可能增长}；不只盯着立即奖励，还看未来；若当前动作未来能带来更高 Q 值→背书它，否则贬低它。
- 公式（p.16）：Q(S_t, A_t) ← Q(S_t, A_t) + η·[ R_{t+1} + γ·max_a Q(S_{t+1}, a) − Q(S_t, A_t) ]
- **η 学习率**：控制 Q 表学习多快；学太快性能可能变差；课件例 η=0.1（Workshop 3 用 0.628）。
- **γ 折扣因子**：下一状态的 Q 值对当前影响应更小，乘 <1 的 γ；课件例 γ=0.99（Workshop 3 用 0.9）。
- 数值例（p.17）：Q(S0, Right) = 0 + 0.1×(1 + 0.99×0 − 0) = **0.1**。
- 若 γ·max_a Q(S_{t+1},a) − Q(S_t,A_t) > 0，说明该动作可能有增益 → 给当前 (state,action) 更大 Q 值；反之亦然。
- 反例（p.18–19）：老鼠随机向下喝毒药 −10 → Q(S1, down) = 0 + 0.1×(−10 + 0.99×0 − 0) = **−1**，表示“下次到此处要避开这个动作”。
- 训练一段时间后 Q 表足够聪明，老鼠倾向 exploitation，按 Q 表选正确路径（p.20）。

### 19. Deep Q-Learning（p.21）
- Q-learning 只适合状态/动作数少的问题；现代游戏 Q 表会巨大无比。
- **Deep Q-Learning**：不用查表，用深度神经网络直接生成 Q 值——输入状态，输出该状态下每个动作的 Q 值（近似）。
- DQN 能处理巨大状态空间；GPU 加速训练与推理。

### 20. Workshop 3 · OpenAI Gym 的 FrozenLake（p.22）
- OpenAI Gym：开源 Python 库，用于开发与比较 RL 算法；提供连接学习算法与环境的**标准 API**，以及一套符合 API 的标准环境（FrozenLake 是其一）。
- 目标：训练 agent 走过冰湖到达 Goal，避开 Holes；冰面滑，agent 只有 **1/3 概率按指定方向移动**。

## 🃏 考点速记卡
1. **Game AI 的目标**：好玩、有挑战不过分、公平、守规则、省资源。（Part I p.6）
   - 易错：不是“最强”，而是“好玩”。
2. **FSM 四要素**：状态、转移、条件、事件/动作；缺点是可预测、状态多时图爆炸。（p.8–11）
3. **ML 在游戏中的五种用途**：智能 NPC、图形增强、对话生成、故事/世界生成、沉浸感。（p.12）
4. **RL 定义**：试错交互 + 奖励反馈；目标最大化累计奖励；四要素 Agent/Environment/State/Action/Reward。（Part II p.5,7）
5. **探索 vs 利用**：ε 控制；训练初期 ε 大（探索），后期 ε 小（利用）。（p.11–12）
6. **Bellman 方程**：Q ← Q + η[R + γ·max Q(next) − Q]；η 学习率、γ 折扣因子。（p.16）
7. **Deep Q 的动机**：状态空间太大，Q 表装不下 → 神经网络近似 Q 值。（p.21）
8. **FrozenLake 关键参数**：is_slippery 时只有 1/3 概率沿指定方向走；状态编号 = row×4+col；动作 0/1/2/3 = 左/下/右/上。
